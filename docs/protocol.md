# Протоколы K2 HE и Keychron Link

Что удалось восстановить по коду Keychron Launcher, форку QMK от Keychron (`Keychron/qmk_firmware`, ветка `2025q3`, `keyboards/keychron/common`) и опытам на живом устройстве. Всё неофициально.

## Устройства

| Устройство | VID:PID | Интерфейс |
|---|---|---|
| K2 HE ANSI | `3434:0E20` | raw HID, usage page `0xFF60`, usage `0x61`, 32 байта |
| Keychron Link (приёмник) | `3434:D030` | raw HID `0xFF60`; для прошивки интерфейс с usage page `0x8C` |
| Keychron Link, загрузчик | `3434:D000` | |
| K2 HE в DFU (STM32) | `0483:DF11` | |

Raw HID клавиатуры появляется, когда она подключена кабелем и переключатель стоит в USB. В положениях BT и 2.4G кабель только заряжает.

## Команды клавиатуры (первый байт репорта)

Из `keychron_raw_hid.h`:

| Байт | Команда |
|---|---|
| `0xA0` | `KC_GET_PROTOCOL_VERSION` |
| `0xA1` | `KC_GET_FIRMWARE_VERSION` (строка `v1.3.0 2026-05-26-...`) |
| `0xA2` | `KC_GET_SUPPORT_FEATURE` |
| `0xA3` | `KC_GET_DEFAULT_LAYER` |
| `0xA7` | `KC_MISC_CMD_GROUP` |
| `0xA8` | `KC_KEYCHRON_RGB` |
| `0xA9` | `KC_ANALOG_MATRIX` |
| `0xAA` | `KC_WIRELESS_DFU`: проброс в радиомодуль |
| `0xAB` | заводской тест |

### Заводской тест `0xAB`

Пакет: `AB <cmd> 00 ...`, в байтах 30–31 контрольная сумма: сумма байтов `1..28`, little-endian.

| cmd | Ответ |
|---|---|
| `0x05` | `AB 05 <transport> <usb_power>`; transport: 1 = USB, 2 = Bluetooth, 4 = 2.4G |
| `0x08` | время сборки, ASCII (`v1.3.3 2026-05-26-10:47:58`) |
| `0x09` | UID микроконтроллера |

Номер версии в `0xA1` и `0xAB 0x08` может различаться: на нашем экземпляре 1.3.0 и 1.3.3.

## Радиомодуль через `0xAA`

Основной STM32 пересылает пакет в модуль (семейство LKBT51) по SPI. Формат запроса:

```
AA <type> <len> <~len> <seq> <payload ...> <checksum16 LE>
type: 0x55 без подтверждения, 0x56 с подтверждением
len : длина payload + 2 байта контрольной суммы (+ служебные, см. код)
```

Ответ модуля приходит в репорте с первым байтом `0x03`, дальше `AA 57 <len> ...`.

| Команда | Назначение |
|---|---|
| `0x60` | информация: модель (`KCH_KB1`), версия прошивки, версия железа |
| `0x61` | версия загрузчика (DFU) |
| `0x62` | начать DFU |
| `0x63` | подготовка, аргумент: версия DFU |
| `0x64` | блок данных, 16 байт, порядковый номер 1..255 по кругу |
| `0x65` | проверка: CRC32 файла **без финального XOR** (`zlib.crc32(data) ^ 0xFFFFFFFF`), дважды |
| `0x66` | переключиться на новую прошивку |

Точная раскладка байтов в `k2he_radio_update.py`.

## Приёмник Keychron Link

Команды из бандла Launcher:

| Байт | Команда |
|---|---|
| `0xB1` | `FR_GET_PROTOCOL_VERSION` |
| `0xB2` | `FR_GET_STATE`: слоты спаренных устройств |
| `0xB3` | `FR_GET_FW_VERSION` |
| `0xBA` | `FR_DFU_OVER_VIA` |

Ответ `0xB2`: `B2 01 <slot0: vid_lo vid_hi pid_lo pid_hi status> <slot1 ...> <slot2 ...>`, status ненулевой означает «подключено». Пример: `b2 01 34 34 20 0e 00` = слот 0 хранит `3434:0E20`, связи нет.

Команда `0x67` переводит приёмник в загрузчик `3434:D000`. Версия в USB-дескрипторе `REV_=300` означает прошивку d.3.0.

## Launcher API

```
GET https://launcher.keychron.com/vapi/v2/product/<id>    # описание + последняя прошивка
GET https://launcher.keychron.com/vapi/v2/firmware/<id>   # все версии, ссылки, changelog
```

`id` это VID и PID одним 32-битным числом:

| Устройство | id |
|---|---|
| Keychron Link Type A (`3434:D030`) | `875876400` |
| K2 HE ANSI (`3434:0E20`) | `875826720` |
| модуль KCH_KB1 (`FF99:FF99`) | `4288282521` |
| модуль CKBT51 (`FF99:FF98`) | `4288282520` |
| модуль KCH_KB2 (`FF99:FF97`) | `4288282519` |
